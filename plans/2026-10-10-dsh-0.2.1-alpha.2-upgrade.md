## 一、审计结论（alpha.1 → alpha.2，本插件消费面）

前置事实：**本插件对 DSH 零编译期耦合**——`src/ lib/ scripts/ test/` 内没有任何
`@deepseek-ai/*` 的 import/require（仅注释提及）。宿主契约全部是运行时 duck-typing，
因此审计口径是「**运行时 API 面是否变化**」，而非编译兼容。

## 三、兼容门实算（三产物判定）

调用 fork 内**真实的** `evaluatePluginCompatibility`（`packages/boot/app-boot/src/plugin-compatibility.ts`），
runtime 传 `0.2.1-alpha.2`：

| 产物 | peer 条数 | 判定 |
|---|---|---|
| 桌面 profile 原装 `2.0.1` | 0 | ADMITTED（但客户端为 0.1.6 世代，见下） |
| npm registry 最新 `2.1.2` | 7（左支 `<0.2.0`） | **DENIED** |
| 本仓 HEAD `2.1.3 / 2.1.4` | 7（左支 `<1.0.0`） | **ADMITTED** |

被拒行的处置（`packages/boot/app-boot/src/compatibility-preflight.ts:114`）是
`row.disabled = true` + stderr `dsh: disabling profile plugin ...`——**整包静默不加载，界面无提示**。

> 预发布口径（`includePrerelease: true`）：边界版本自身的预发布仍「小于边界」。
> 旧上界 `<0.2.0` 当年正是靠这条规则在 `0.2.0-rc.*` 上侥幸成立（`0.2.0-rc.2 < 0.2.0`），
> 上游一旦跨到 `0.2.1-alpha.*` 即失配——这是 v2.1.2 线上被禁用的完整成因。
> 同口径下 `1.0.0-rc.1` 对 `<1.0.0` 也是放行的。
