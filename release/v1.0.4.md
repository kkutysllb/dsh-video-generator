# v1.0.4（2026-09-09）

## 版本信息

- **版本**：1.0.4
- **日期**：2026-09-09
- **tag**：`v1.0.4`
- **主题**：生成、评审和模型管理统一以用户默认通道配置为准
- **发布形态**：源码构建、npm 本地包、dsh-plugins 镜像

## 修复

- 移除流水线内置的具体 image/video 默认模型。`master-asset`、`shot-assets`、`video` 和评审重拍现在每次执行都从当前默认通道的 `models[]` 选择模型。
- 同一种 `kind` 配置多个模型时严格使用 `models[]` 中的第一项：`image`、`video`、`tts` 分别独立选择。
- 生产路径不再使用 `VGEN_VIDEO_MODEL` 覆盖通道模型；测试仍可通过内部依赖注入覆盖模型。
- `final-cut` 配置 `kind=tts` 时使用通道中第一个 TTS 模型；没有 TTS 模型时保留现有 macOS `say` / Windows SAPI 本地回退。
- 宿主默认通道解析现在携带 vault 中的 `models[]`；旧 `vault.json` 缺少该字段时运行时按空列表兼容，不增加迁移字段。
- 显式配置但目录未识别的 `kind=video` 模型不会静默落到 Kling 的 text-to-video Provider，而是进入现有 DashScope image-to-video 适配器；已知 `kling-*` 仍保持 Kling 路由。

## 新增错误语义

新增统一 `model-unavailable` 错误，包含当前通道 id/名称、模型 kind、具体模型名（缺失时为“未配置”）和操作建议：

> 请在设置页切换默认通道，或测试并重新配置模型。

以下情况使用该错误：

- 默认通道不存在或没有对应 kind 的模型；
- 配置模型对应的 Provider 不支持当前阶段能力，例如不能执行 image-to-video；
- 上游明确返回 404、422，或 400 且消息明确表示模型/分发渠道不存在或不可用。

429、超时、网络错误、临时饱和和普通任务失败不误报为 `model-unavailable`，继续使用原有重试或失败语义。模型校验在消费确认之前完成，缺模型或能力不匹配不会产生确认和 `spend` 事件。

## 模型管理 UI

- 模型面板每行增加可见的“移除/Remove”按钮，带 `title` 和 `aria-label`。
- 移除和取消勾选只修改当前面板草稿，点击“保存选中/Save selected”后才通过现有 `channels.update` 落盘。
- 保存只提交当前 picker 中仍勾选的模型；允许提交 `models: []`，因此取消全部模型后可以真正删除通道中的模型。
- 更新了中英文文案和 `src/client/index.ts` 功能说明。

## 兼容性与升级说明

- 旧 `vault.json` 无需迁移，现有三要素和版本字段保持兼容。
- 已有运行目录、视频素材和 run 状态不做迁移；发布后可从已有 run 的 `video` 阶段继续。
- 后续切换默认通道或模型只需在 Web 设置页修改，不需要修改插件代码，也不需要因为模型选择反复重启引擎。
- 免费档视频模型可能带平台水印，介意时请在设置页切换付费模型。
