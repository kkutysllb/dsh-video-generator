     `plugin-compatibility.ts` 同库同口径）钉死：`0.1.0-rc.5`/`0.1.7-rc.2`/`0.2.0-rc.2`/
     `0.2.1-alpha.1`/`0.2.1-alpha.2`/`0.2.2`/`0.9.9` 放行，`1.0.0`/`2.0.0` 拒绝，
     `3.0.x` 放行、`4.0.0` 拒绝；并自证「旧上界 `<0.2.0` 对 0.2.1-alpha.2 求值 false」这一失配事实。
  2. **inject 清单**：会话桥 v4 所需的 6 个引擎包齐备、0.1.7 已删包 `dsh-client-runtime` 不回流。
  3. **会话桥 v4 主路径关键串在场**（`retainedBy`/`mainView`/`"uiWorkspace"`/`openSession`/
     `.using(`/`sessions.scope`/`sessions.binding`/`conversation.input`/`.for(actx)`/

  6. **版本同源**：`PLUGIN_VERSION == package.json.version`。

## 修复

- **无代码缺陷修复。** 本版真正交付的是**发布渠道缺口**：v2.1.3 的兼容门修复
  （左支上界 `<0.2.0` → `<1.0.0`）停留在仓库里未发布，而 registry 上的 2.1.2 仍带旧范围——
  在 0.2.1-alpha.x 上会被 app-boot 的 `compatibility-preflight` 整包静默禁用
  （stderr 仅一行 `disabling profile plugin`，界面无任何提示）。
- 顺带记录一个**仍会在旧安装上出现**的现象（本版可解）：2.0.1 无 peer 声明故被兼容门放行，
  但其客户端是 0.1.6 世代——`SessionListState.current` 与 `ISessions.open()` 自 0.1.7 起已删，
  表现为「每次点『发送指令』都新建一个会话且不跳转，『打开会话』按钮无反应」。升级到 2.1.x 即恢复。

## 兼容性与升级说明

- **零破坏性变更**：`lib/**`（host 半、client bundle）、路由面、工具面、vault/run 数据结构全部未改；
  本版改动集中在测试、文档与版本号。
- **兼容门范围不变**：`>=0.1.0-rc.5 <1.0.0 || >=3.0.0 <4.0.0`（7 条 peer 全部 optional）。
  实测放行：`0.2.0-rc.2` / `0.2.1-alpha.1` / `0.2.1-alpha.2` / `3.0.x`；拒绝：`1.0.0` 起。
  注意宿主口径是 `includePrerelease: true`——**边界版本自身的预发布仍算小于边界**
  （`1.0.0-rc.1` 会被放行；旧上界 `<0.2.0` 当年也是靠这条规则才在 `0.2.0-rc.*` 上侥幸成立，
  跨到 `0.2.1-alpha.*` 即失配）。
- **升级方式**：由插件管理检测到 2.1.4 后手动更新；数据无需迁移。
- **临时兜底（仅当无法立即升级）**：对已装的 2.1.2 可精确豁免
  `dsh plugin allow-version dsh-video-generator@2.1.2 0.2.1-alpha.2 --accept-risk`；
  但请优先升级——豁免只是压制症状。
