## 新增

### 会话桥 v4（DSH 0.1.7 契约对齐）

- **当前会话判定**：0.1.7 的 `SessionListState` 删除 `current` 字段，改为按
  `byId[id].retainedBy.mainView>0` 判定（uiWorkspace navigation 以 `retain(target,{source:'mainView'})`
  持有选择态）；旧宿主（≤0.1.6）回退快照上的 `current` 字段，双世代兼容。
- **选中并展示会话**：`sessions.open()` 在 0.1.7 已删除，改走 `uiWorkspace.openSession(target)`
  （可选面经 `ctx.get` 软探测，缺席回退旧宿主 `sessions.open`）。「打开会话」按钮在 0.1.7 上恢复可用。
- **持引用递送**：0.1.7 的 `fillDraft` 内部按 `sessions.binding(sessionId)` 寻址——会话必须
  处于 retain 状态才有输入壳。递送期改用 `sessions.using(id, {source:'dsh-video-generator'}, op)`
  持引用（回调结算自动 release），壳解析沿 `conversation.input.for(actx)`（与 fillDraft 同口径）。
- **诚实落地**：预填重试窗口 8×250ms（`openSession` 后输入壳可能迟到位）；落地才报 `prefilled`，
  未落地如实降级 `copied`/`none`（剪贴板始终同步写入兜底）——不再"fillDraft 一调就报成功"。
- `lib/client.js` 新增 `exports.__testHooks`（currentSessionId / inputShellFor / prefillToSession /
  openSessionView / sendInstructionFor）供契约冒烟直调；`src/client/index.ts` 类型参考同构更新
  （`VgenSessionsFace` 0.1.7 形状 + v4 七函数镜像）。

## 变更

- **manifest（两通道同改）**：`dsh.client.inject` / `qilin.client.inject` 删除
  `@deepseek-ai/dsh-client-runtime`（**0.1.7 已删包**），按实际消费面补齐 6 引擎包：
  `@deepseek-ai/dsh-api-session-controller`、`@deepseek-ai/dsh-client-locale`、
  `@deepseek-ai/dsh-client-ui-conversation`、`@deepseek-ai/dsh-client-ui-layout`、
  `@deepseek-ai/dsh-client-ui-slots`、`@deepseek-ai/dsh-client-ui-workspace`。
- **peer 兼容门声明（新）**：`peerDependencies` 7 条（`@deepseek-ai/dsh` ∪ inject 清单），范围
  `">=0.1.0-rc.5 <0.2.0 || >=3.0.0 <4.0.0"`；`peerDependenciesMeta` **全部 optional**。
  - 0.1.7-rc.1 起宿主按 peer 范围对运行时版本做 `semver.satisfies(..., {includePrerelease:true})`
    强校验（安装期 + 启动期，不满足拒装/拒启，`dsh plugin allow-version` 可精确豁免）——
    声明使兼容性可被插件管理器判定，0.2.x 及未验证大版本默认拒绝。
  - 右支 `>=3.0.0 <4.0.0` 为 QiLin 3.x 运行时号预留（2.0.1 已实证 QiLin 3.0.2+ 兼容；
    兼容门把每个 dsh peer 都对**运行时版本**校验，纯 `<0.2.0` 会被 QiLin 同款门误拒）。
  - **optional 是硬要求**：非 optional 的宽范围 peer 会让 pnpm 静默把整棵引擎树拉进用户 profile；
    optional 后安装面零污染，而兼容门不看 meta ⇒ 门禁照常强制。
- 版本 2.0.1 → 2.0.2；`PLUGIN_VERSION` 同步 2.0.2（`/health` 与设置页「环境与诊断」上报）。

## 修复

- **0.1.7 上任务指令发送桥静默失效**：症状①——「发送任务指令」预填永远不生效，恒降级
  "请粘贴到对话"；根因：`fillDraft` 改按 `binding(sessionId)` 寻址，未 retain 的会话直接 no-op，
  而旧代码调完就报 `prefilled`。修后：递送期持引用 + 壳挂载重试 + 诚实回报。
- **0.1.7 上「打开会话」按钮完全不动**：根因：`sessions.open()` 已删除，旧代码
  `typeof ctx.sessions.open === "function"` 守卫静默吞掉。修后：走 `uiWorkspace.openSession`，
  旧宿主回退 `sessions.open`。
- **新建会话恒落空**：根因：`list.getSnapshot().current` 字段已删，"无当前会话"判定恒真 →
  每次都新建会话（旧宿主行为也一并修正为同一条判定链）。

## 删除

- manifest 中的死包声明 `@deepseek-ai/dsh-client-runtime`（0.1.7 已删包；功能无损，
  `ctx.effect` 等由 cordis 自带）。

## 兼容性与升级说明

- **宿主要求**：DSH **0.1.5+**（不变）；0.1.7-rc.2 为本版验证目标。0.1.7 的
  `SessionListState`/`ISessions` 新面与 ≤0.1.6 旧面**双世代兼容**（软降级路径全覆盖，
  契约哨兵钉死 `getSnapshot().current` 死用法不复现）。
- **QiLin**：`qilin.*` 双通道键原样保留，行为一致；升级需 QiLin 3.0.2+（同 2.0.1）。
- **升级无迁移**：数据根、vault、runs 存储口径均不变；`dsh plugin add` / 插件管理器更新即可。
- **插件管理器可见变化**：安装/启用时会做 peer 兼容门校验（本版声明全部命中 0.1.5→0.1.7-rc.x
  与 QiLin 3.x）；若在未来未验证的运行时上被拒，可用 `dsh plugin allow-version` 精确豁免。
