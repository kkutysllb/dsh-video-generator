## 新增

### QiLin（麒麟）双通道适配

- `package.json` 同时声明 `qilin.bundle.patch` / `qilin.client` 与 `dsh.bundle.patch` / `dsh.client`，指向同一份 `cordis.patch.yml` 与 client 交付物，行为完全一致。QiLin（dsh 0.1.6-alpha.2 合并后）的插件管理器只认原生键 `qilin.bundle.patch`（缺失报「没有声明组合包」）；DSH 宿主仍读 `dsh.*`，互不影响。
- 补 `repository` 字段，支持 `qilin plugin add github:kkutysllb/dsh-video-generator` GitHub 直装。
- README 新增「麒麟（QiLin）引擎安装」章节：
  - 必须经 `qilin plugin --profile qilin add` 装进 profile（包落 profile 私有 `~/.qilin/profiles/<name>/node_modules`，裸包名原生解析第一跳）；**不要**手工放共享 `~/.qilin/profiles/node_modules`——alpha.2 起该目录为安装保留区，放那里的包激活时直接 `failed to import`。
  - 引擎版本要求：运行需带 dsh 兼容层的 QiLin 3.0.0+；插件管理（设置页展示/启停）要求 3.0.2+（只认 `qilin.bundle.patch` 原生键）。
  - 运行时解析：dsh alpha.2 起依赖解析默认运行时模式，插件运行期导入由 profile 安装图经进程内 generation 解析；引擎包按框架契约声明于 peerDependencies。

### 宿主家目录单一事实源

- 新增 `src/store/home.ts` 的 `harnessHome()`：`QILIN_HOME → DSH_HOME → homedir()`（env 均缺席返回 null，调用方回退 `homedir()`）。QiLin 启动器注入 `QILIN_HOME` 并把 `DSH_HOME` 钉到同一处，两种读法都落麒麟家目录。
- runs / vault 存储根统一切换到该口径：QiLin 部署下运行数据落 `~/.qilin/.dsh-video-generator/`；DSH / KCoder 桌面端不受影响；裸 node 直跑保留 homedir 历史行为。口径与 dsh-super-ppts、dsh-skills-stock、dsh-ssh-remote 一致。

### 宿主生命周期中断（stop billing on deactivate）

- 插件停用/卸载（HMR 重载）时宿主 `AbortController.abort()`：在飞 `vgen_generate` 在**段边界**与**并发泵取任务前**检查点停下，running 段置 failed、run 置 `failed(host-interrupted)`、追加 `run-interrupted`（reason: host-deactivated）事件留痕，**不再继续调用通道 API 计费**（在飞请求自然结束，不取新任务）。
- 新增 `RunInterruptedError`：`vgen_generate` 返回 `interrupted` 错误信封，提示插件重新启用后可对未完成段 `rerunStage` 续跑。语义与 dsh-kylin-automation 的 host_interrupted 同款；`interruptMarked` 保证并发泵多 runner 同时命中时事件只记一次。

### 客户端样式卸载收口

- `ensureStyles()` 从「插入即忘」改为返回移除函数并注册 `ctx.effect`：插件 fiber 卸载时样式标签随之移除；重复挂载返回 null，不动既存标签，修复反复挂载/卸载的样式泄漏。

## 变更

- 版本 2.0.0 → 2.0.1；`PLUGIN_VERSION` 同步 2.0.1（`/health` 与设置页「环境与诊断」上报）。

## 兼容性与升级说明

- **DSH / KCoder 用户无感**：`dsh.*` 键原样保留，数据根仍读 `DSH_HOME`，无迁移。
- **QiLin 用户**：升级需 QiLin 3.0.2+；首次安装务必走 `qilin plugin add`，数据自动落麒麟家目录。
- 中断语义只影响「停用/卸载时刻在飞的 run」：已 done 的 run 不动；被中断的 run 重新启用插件后 `vgen_generate { runId, rerunStage: "<未完成段>" }` 续跑。
